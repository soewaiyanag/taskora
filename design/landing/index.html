Calm by default.

Most task tools show everything at once. Taskora shows the work, and keeps the rest one step away.

  1. Quiet until you ask.

    The board stays white. Colour appears when you ask whose work is whose, and settings stay out of sight until you need them.

  2. Done the moment you do it.

    Moves, ticks and comments show up instantly. If the server disagrees, the change rolls back and says why.

  3. Your hands stay on the keys.

    ⌘K finds any task or person. C adds a task, 1 to 5 shows a teammate’s work, and Shift with an arrow moves a card.

How it’s built.

A Go API and a React app, designed contract-first. Follow one card move from Mai’s screen to Jonas’s.

  1. Mai drops the card.Her board updates at once, before the server answers.
  2. The Go API checks it.Session and workspace membership first, then the move is saved.
  3. PostgreSQL commits.The new status and position land in one transaction.
  4. The hub publishes.One event goes out over channels to every open connection.
  5. Redis fans it out.Every API instance hears about the move, however many are running.
  6. Jonas’s board catches up.The event lands in his cache and the card moves.

One contract, two compilers.

The API is written down first, as an OpenAPI contract. The Go server and the React app both generate their types from it, so a renamed field breaks the build on both sides before it can reach a user. Database queries get the same treatment: sqlc turns SQL into typed Go.

openapi.yaml
Task:
  type: object
  properties:
    statusId:
      type: string
      format: uuid
Go server · oapi-codegen
move.Status = req.StatusID

req.StatusID undefined (type MoveTaskRequest has no field or method StatusID)

React app · orval
card.status = task.statusId

Property 'statusId' does not exist on type 'Task'.

Works without the server
The demo runs on a mock API in the browser that follows the same contract, so it never goes down.
Workspaces stay separate
Every query is scoped to the member’s workspace, and tests try to cross over on purpose.
A real database in tests
Integration tests run against PostgreSQL in Docker, not mocks.
Sessions that can’t be replayed
Refresh tokens rotate on every use. Reusing an old one ends the session.
